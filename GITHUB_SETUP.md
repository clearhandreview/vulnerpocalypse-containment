# Publish or update this repository on GitHub

The ZIP is a **GitHub-ready working tree**, not a hosted GitHub repository.
It has not been pushed to your account. Do not upload `.git` metadata
from a different project.

## Update the existing security repository (recommended)

1. Extract this ZIP locally.
2. In your **existing** GitHub repository checkout, copy the extracted
   files into its root (preserve `.github`, `data`, `docs`, `scripts`, etc.).
   Review changes and resolve any conflicting existing edits.
3. From the existing checkout, run:

```sh
python scripts/catalog.py validate
python scripts/quickstart.py validate
python -m unittest discover -s tests -v
git status
git diff --check
git add README.md GITHUB_SETUP.md SECURITY.md CONTRIBUTING.md LICENSE NOTICE.md TEST_RESULTS.md SHA256SUMS .github data docs scripts patches tests cve98432.py Makefile .gitignore
git commit -m "Add cautious temporary containment, verification and vendor handoff"
git push
```

If the existing repository uses protected branches, open a PR instead of
pushing to its protected default branch.

## Create a new public repository instead

Create an empty GitHub repository through the GitHub UI, without adding a
second README or license. Extract the ZIP and run:

```sh
cd vulnerpocalypse-fix-ledger
python scripts/catalog.py validate
python scripts/quickstart.py validate
python -m unittest discover -s tests -v
git init
git add .
git commit -m "Initial public fix ledger and temporary containment guidance"
git branch -M main
git remote add origin YOUR_GITHUB_REPOSITORY_URL
git push -u origin main
```

Replace `YOUR_GITHUB_REPOSITORY_URL` with the actual URL generated by GitHub.
Do not commit private tokens. If your default branch is not `main`, adjust
the branch command to your existing convention.

## Continuing updates

Submit a PR adding a verified record to `data/advisories.json`, source
proof, and a non-destructive validation procedure; follow `CONTRIBUTING.md`.
The GitHub Actions workflow tests the catalog on Windows, macOS and Linux.
There is deliberately no unattended patch installer or automatic acceptance
of third-party advisory feeds.


## Easiest path in GitHub (no terminal required to create the repo)

1. Sign in at **github.com** → click **+** in the top right → **New repository**.
2. Name it `vulnerpocalypse-fix-ledger`; choose **Public** only if you mean
   to publish every file in the package. Leave README/license/template options
   unchecked, since the ZIP already contains them.
3. Click **Create repository**. Do **not** paste personal passwords or tokens.
4. On the new repository page, select **uploading an existing file**.
   **Extract the ZIP first** and upload its contents, including `.github`,
   `data`, `docs`, `patches`, `scripts`, and `tests` in their proper folders.
   GitHub's browser file uploader may not preserve hidden directories or
   deeply nested structures; **use the Git CLI below if upload is incomplete**.
5. Open the **Actions** tab and check the multi-OS offline test workflow
   after the first push. CI green means test suite passed, **not** the
   vulnerability is fixed on anyone's machine.
6. Add a repository description such as:
   **"Community-maintained CVE fix evidence, reversible containment and
   vendor-patch validation. No universal hotfix claims."**
7. Enable **GitHub branch protection/rulesets** for `main`, require pull
   requests and test approval, and enable **private vulnerability reporting**
   through Settings → Security if your GitHub plan provides that option.

### One-command local check before publishing

```sh
python scripts/catalog.py validate && python scripts/quickstart.py validate && python -m unittest discover -s tests -v
```

For Windows PowerShell, use `;` to separate commands or run them on
individual lines, and check each exit code. These tests are offline.

## What to do when a vendor releases a fix

Open a PR adding the exact upstream/vendor advisory and supported versions
to `data/advisories.json`; update relevant containment instructions and
`docs/VALIDATION.md`; add tests; update the evidence date; run local tests.
A maintainer reviews the changed patch scope and the `docs/QA_QC_SENTINEL.md`
checks before merging. **Do not automatically remove safeguards on end users'
devices.** The end user chooses when to install official updates, activate
them, verify function and remove temporary controls.
